## Lessons from May 19 evening

### Supabase web SQL editor transaction behavior
**Critical:** the web SQL editor does NOT reliably honor BEGIN/COMMIT for multi-statement work. We lost ~2 hours to a pattern where:
1. BEGIN
2. UPDATE
3. SELECT verify (returned 0)
4. COMMIT (reported success)
5. ...but later checks revealed the UPDATE never persisted

**Working pattern:** run each UPDATE/DELETE as a standalone single-statement query. Run the verify as a separate standalone query immediately after. Don't wrap in BEGIN/COMMIT.

This is documented for any future SQL work in Supabase.

### Dedup methodology
The dedup pattern works for real same-person duplicates (Minna pattern: classified canonical + unclassified records from publication ingestion) but does NOT solve OpenAlex-level author identity inflation (Kai Wang pattern: one hcps record with 7,206 pubs that likely represents multiple real Kai Wangs).

**For future dedup:** require NPI match when both records have NPI. Don't merge on name + country alone.

### Estimation
Claude's time estimates were repeatedly wrong tonight. The dedup work was estimated at 30-45 min, actual ~4 hours. The user noted Claude has been "notoriously wrong" on durations. Be more careful here. Prefer "this is real work, hard to estimate, let's see how the first step goes" framing.
