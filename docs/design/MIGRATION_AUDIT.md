# Design-system migration audit

**Read-only inventory.** No code was changed producing this document. It maps every FieldMark
surface against the design-system migration (foundation `314a9bf` → list `b077d02` → profile
`e2dcda6`; Pulse prototype `a0b92d5`) so future passes can be sequenced and de-risked.

**Legend**
- **State** — DONE / PARTIAL / UNTOUCHED / ORPHAN (dead code)
- **Surface** — *warm* = design-system `#171512`; *cool* = old utility palette (`#0A0A0B` page,
  `#111113`/`#0D0D10`/`#0F0F12`/`#15131A` cards). Every unmigrated surface is cool + 100% inline-styled.
- **Inherit** — does it render an already-migrated component (partial visual inheritance)?
- **Scores / Accents / Narrative** — does it touch the open data threads (score-floor, cohort colors, AI prose)?

## 3. Flag — cohort scores NOT going through `formatScoreFloor1`

`formatScoreFloor1` (`lib/cohort-metrics.ts:43`, foundation) is consumed **only** by `HCPCard`,
`ScoreBreakdownV3`, and `ScoreBreakdownV3Rising`. Every other surface that renders a cohort score
still uses raw `Math.round`, so a scope topping out at 99.82 will display an **invented `100`**:

| Surface | Location | Code | Severity |
|---|---|---|---|
| **SearchBar** (shared via TopBar) | `SearchBar.tsx:44` | `Math.round(result.cohortScore).toLocaleString()` | **Highest** — the search dropdown appears on *every authenticated page* |
| **Brief header** | `BriefHeader.tsx:88` | `Score {Math.round(hcp.score)}` | High — key per-HCP feature |
| **Landscape quadrant** | `LandscapeQuadrantChart.tsx:82–83` | `Math.round(point.momentum_composite)` / `visibility_composite` | Medium — chart axes/tooltips |
| **Top Collaborators chip** | `MiniCollaboratorNetwork.tsx` | `Math.round(c.cohort_score)` in the `EST/RS` chip | Low — intentionally left integer (small chip, not the hero numeral); noted for consistency |

> Recommend routing all four through `formatScoreFloor1` when their surfaces are migrated (SearchBar
> first — it's global and one line).

## 4. Flag — narrative / AI-generated prose beyond the migrated three

The migrated narrative treatment (serif + amber thesis rule) covers **Why This Expert**,
**Signal Summary**, and **Belief Profile** only. These other prose blocks are the same class as the
Community engagement-narrative issue and are still unmigrated (plain sans, no editorial voice, no
provenance treatment):

| Block | Location | Kind |
|---|---|---|

| **Community engagement greenfield note** | `DetailScreen.tsx` `EngagementMixBlock` (`isResearchCohort` sentences) | **Template narrative** on the migrated profile — the referenced Community issue; still plain |
| **HCP positions** | `HcpPositionsPage.tsx:256/:269` (`position_text`, `evidence_excerpt`) | **LLM-extracted** prose |
| **Field Insights / Recent Insights** | `FieldInsightsScreen.tsx`, `RecentInsightsTile.tsx` (`body`, `why_it_matters`) | User-authored (not AI) — narrative blocks nonetheless |

> The **Brief** and **Home AI-Synthesis** blocks are the two that most need the serif/provenance
> treatment *and* a "this is a FieldMark/AI claim" marker, since they're generated.
