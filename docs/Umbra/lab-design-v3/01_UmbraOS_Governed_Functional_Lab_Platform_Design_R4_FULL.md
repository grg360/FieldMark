## Final platform correction

The generic platform now admits a complete immutable schema bootstrap artifact
as a first-class Lab input. Application profiles declare the required object
classes; a deterministic completeness inspection records hashes, counts,
row-data and sensitive-value scans, disposition and limitations. Admission
does not equal execution proof. A newly created empty Lab database must replay
the admitted dump and profile live-object manifest before Wave 1 can pass.

The first topology remains `LOCAL_POSTGRES_PLUS_MANAGED_WORKTREE` on the
existing 32 GB K11. Services should be sequenced when useful and actual memory
captured. No additional hardware is a prerequisite. Rootless OCI remains
`FOLLOW_ON_PLATFORM_MILESTONE` with parity target
`ACCEPTED_BREAST_FUNCTIONAL_BUILD`.

## Control boundaries

The platform retains explicit `LAB_COMMAND_ADMISSION_MANIFEST`,
`DEFAULT_DENY_WITH_RUN_SCOPED_ALLOWLIST`, manifest-driven reset, durable
evidence outside disposable state, no production credentials, and separate
Foundation/run/promotion authorizations.

FieldMark v2 targeting is now an application safety invariant with code-level
preflight and post-run validation. The platform records governed mode, target
version, input assertions and evidence; it does not rely on operator memory.

## Transitional operating model

Manual engineering tickets are scaffolding for missing platform or application
safeguards. After accepted Foundation and v2 enforcement, Breast becomes
`CONVERSATIONAL_ORGANIZATIONAL_EXECUTION`: Umbra retrieves the accepted
profile, proposes waves and authority, negotiates scope, creates internal work,
executes only approved stages, returns evidence, and pauses for judgment.
