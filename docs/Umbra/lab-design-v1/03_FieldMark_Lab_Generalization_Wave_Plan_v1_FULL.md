## Wave 3 — Backend, SQL and pipeline generalization

consumer, Scientific Pulse SQL, backend scripts, TA maps/allowlists, scoring,

development review.

## Wave 4 — Frontend generalization

Generalize indication routes, API defaults, parent selection, Community,
Scientific Pulse, Telescope TA-keyed files, hidden Breast, and loading/empty/
error/unavailable/unvalidated-domain states. Preserve NSCLC. Reported maximum
wave touches roughly 31 frontend files, pending source inventory. Exit:
responsive multi-indication acceptance and NSCLC regression.

## Wave 5 — Bounded corpus and domain validation

Admit an authorized public-source package; no paid narrative/theme calls.
Run dedup detection only. Bound OpenAlex by package admission while retaining
global backlog semantics. Run fragile-identity audit and duplicate-signature
delta. Capture trial and Pulse term hits, zeros, implausibly high counts,
acronym/short-term collisions, representative publications and theme
coherence; return failed terms to the Ontologist. Exit: empirically supported
proposal package ready for founder validation.

## Wave 6 — Functional validation

Compare repeat runs; inspect representative HCP/publication/scoring outputs;
exercise Community, Scientific Pulse and cross-indication UI; run NSCLC
regression; publish vocabulary and full Lab evidence; obtain development and
founder reviews. Exit is Functional Lab acceptance only—not production or
cross-TA safety authorization.

## Gates and stop conditions

Stop for source mismatch, production credential/network presence, unregistered
input, proposal accepted without evidence, unexpected shared-state mutation,
dedup merge attempt, missing reset evidence, identity-guard regression,
duplicate-signature increase requiring review, NSCLC regression, cap breach or
unverifiable evidence. Only the active wave runs; later work is pending or
authorized.
